```markdown
# 对公普惠客户潜力营销访谈提纲模板

> 来源：科技型企业普惠贷款营销访谈提纲模板.xlsx —— “营销”sheet  
> 适用场景：对公普惠客户潜力营销，聚焦网点存量科技型企业未办理普惠信用快贷的原因分析与营销建议。

## 场景信息

- **场景**：普惠客户潜力营销
- **场景说明**：指建设银行拟运用互联网和移动通信等信息通信技术，基于风险数据和风险模型进行交叉验证和风险管理，线上自动受理贷款申请及开展风险评估，并完成授信审批、合同签订、贷款支付、贷后管理等核心业务环节操作，向符合条件的小微企业法人或非法人组织（按照国家有关规定不得办理银行贷款的主体除外）发放的，用于借款人日常经营周转的信用类流动资金贷款业务。
- **子场景**：科技型企业普惠贷款营销
- **子场景说明**：示例：本网点现有的对公客户中，具有科技资质且未申请普惠信用快贷贷款的客户名单及原因，给出营销建议。

## 1. 客户筛选

### 具体方法

1. 筛选客户归属为当前网点，客户账户状态为正常（未销户）。
2. 筛选科技资质企业，可用行内及外部采购的科技型企业标签。
3. 筛选当前未办理普惠信用快贷的客户。

### 知识引用

专家经验：涉及标签包括客户当前状态、对公客户国家瞪羚企业标志、对公客户重大科技项目标志、对公客户国家创新型企业标志、对公客户科技型中小企业标志、对公客户国家重点实验室标志、对公客户国家企业技术中心标志、对公客户技术先进型服务企业标志、对公客户是否是专精特新企业、对公客户国家科技小巨人企业标志、授信客户标志。

### 规则引用

同时满足：

1. 客户所属机构为当前网点。
2. 客户当前状态 = "正常"。
3. 科技型企业：对公客户国家瞪羚企业标志 = "1" OR 对公客户重大科技项目标志 = "1" OR 对公客户国家创新型企业标志 = "1" OR 对公客户科技型中小企业标志 = "1" OR 对公客户国家重点实验室标志 = "1" OR 对公客户国家企业技术中心标志 = "1" OR 对公客户技术先进型服务企业标志 = "1" OR 对公客户是否是专精特新企业 = "1" OR 对公客户国家科技小巨人企业标志 = "1"。
4. 未办理普惠信用贷款客户：在普惠数据表中筛选未办理客户（授信客户标志 ≠ "1"）。

### 专业术语

信用快贷、科技资质、无贷户。

### 关键输出

**名称**：客户筛选  
**描述**：本网点当前未办理普惠信用贷款且账户状态正常的科技型企业共计 XX 户。

## 2. 客户数据匹配

### 具体方法

关联可能影响客户未办理普惠信用快贷的数据字段，包括客户的资产信息、交易行为、成立年限、申请记录等。

### 知识引用

规章制度：建总发〔2024〕446 号《中国建设银行“小微快贷-信用快贷”业务管理规程（2024 年版）》。

借款人及企业主应符合“小微快贷”业务管理要求，并具备以下条件：

1. 原则上借款人成立时间需满 X 年（含），可根据客户情况进行差异化管理。
2. 企业主一般应年满 X 周岁且不超过 X 周岁，非港、澳、台及外籍人士。
3. 借款人信用状况良好，征信记录及在建设银行的贷款风险分类等情况满足系统设定的准入要求。
4. 借款人及企业主在其他银行信贷合作情况满足差别化准入要求。
5. 符合建设银行要求的其他条件。

### 规则引用

1. 当前日期 - 对公客户成立日期 > X days。
2. X < 实控人年龄 < X。
3. 征信记录良好……

### 关键输出

**名称**：客户圈定  
**描述**：满足小微快贷信用快贷的企业共 XX 户。

## 3. 原因归因

### 具体方法

将原因进行拆解，判断是否符合以下三类：

1. **需求端因素**：企业当前无融资需求（现金流充足、轻资产运营），金融总量 > X 或存款日均 > X。
2. **客户有意，但不满足条件**：客户有过申请记录，但被拒绝（不符合基本准入条件或当前有不良贷款记录），可查看当前是否满足申请条件。
3. **产品匹配度不足、未深度触达**：客户有申请记录或客户净流出交易金额、笔数较大证明存在资金缺口，但可能产品额度（300 万）不满足客户需求；利率过高，与同业产品利率进行比较；客户不了解普惠信贷产品。

### 知识引用

专家经验。涉及标签：对公客户金融总量余额、对公客户当前活期存款账户余额、对公客户当日定期存款年日均余额、借方交易金额、贷方交易金额、申贷次数、预测算额度。

### 规则引用

1. 无融资需求：对公客户金融总量余额 > X 或者（对公客户当前活期存款账户余额 + 对公客户当日定期存款年日均余额）> X。
2. 净流出：借方交易金额 - 贷方交易金额。
3. 有过申请：申贷次数 > 0。
4. 产品额度不满足客户需求：预测算额度 < X。

### 专业术语

净流出、客户金融资产、不良。

### 关键输出

**名称**：原因探求  
**描述**：满足上述条件的企业共 XX 户，当前无融资需求的企业 XX 户，申请过信用快贷但未成功办理的企业 XX 户，产品匹配度不高 XX 户。

## 4. 决策建议

### 具体方法

根据归因，给出对应策略，并挑选更有营销潜力的客户清单：

1. 如果是需求原因，可以推荐客户我行其他对公产品，结算类或投资类。
2. 客户不符合准入条件，判断客户不符合的原因是因为客户本身存在风险隐患或是我行信息不完全导致；信息不全的客户可以持续营销客户配合相关材料补充。
3. 产品不匹配，深入开展营销，了解客户需求及不匹配的原因，介绍适合客户的贷款产品。

### 知识引用

规章制度：

1. 建总规章〔2025〕264 号《中国建设银行多模式现金池业务管理规程（2025 年版）》。
2. 建总发〔2020〕364 号《中国建设银行票据池业务管理办法（2020 年版）》。
3. 建总规章〔2025〕123 号《中国建设银行小微企业“善新贷”业务管理规程（2025 年版）》。
4. 建总规章〔2025〕21 号《中国建设银行“善营贷（对公版）”业务管理规程（2025 年版）》。
5. 建总发〔2024〕367 号《中国建设银行小微企业“抵押快贷”业务管理规程（2024 年版）》。

### 规则引用

1. 其他对公结算产品：现金池、一户通、票据池、资金归集等。
2. 其他对公投资：大额存单、黄金积存、基金等。
3. 其他对公普惠贷款种类：抵押快贷、善系列产品、个人经营性贷款等。

### 关键输出

**名称**：总结决策  
**描述**：

本网点当前满足办理普惠信用贷款的科技型企业共计 XX 户，其中“无融资需求”客户 XXX 户；不满足贷款条件客户，共 XX 户；产品匹配度不高，共 XX 户。具体客户清单及维护建议如下：

### 一、“无融资需求”客户

该类客户整体经营稳健，现金流较为稳定，负债率相对较低，对外融资依赖程度不高，短期内暂无信贷需求，但具备较高的综合金融服务潜力，是我行开展综合化、长期化、生态化营销的重要客户群体。针对该类客户，可重点从以下几个方向开展综合营销：

1. **资金管理与账户管理**：结合客户资金归集及内部资金调度需求，推荐现金池、资金归集、一户通、票据池等产品，帮助企业实现多账户资金集中管理，提高资金使用效率，降低资金沉淀成本，同时提升企业财务管理水平。对于集团型客户，可通过搭建统一资金管理架构，增强资金统筹能力，实现资金集中管控与风险隔离。
2. **结算与交易便利性**：结合客户日常经营结算场景，提供便捷的结算服务方案，优化企业收付款流程，提升账户使用粘性。通过优化账户体系结构，提升企业资金流转效率，增强客户对我行基础结算服务的依赖度，形成长期稳定的业务合作关系。
3. **资金保值增值**：根据客户资金沉淀情况，推荐大额存单、结构性存款、黄金积存、基金等产品，满足客户在资金安全基础上的收益提升需求。针对资金规模较大的客户，可提供组合化配置建议，在兼顾流动性的同时，提升资金综合收益水平，增强客户资金留存意愿。
4. **综合服务与客户关系维护**：加强常态化走访沟通，持续关注客户经营变化及潜在金融需求，及时识别客户未来可能产生的融资或投资需求，提前做好业务储备。通过提升服务响应效率及专业化水平，增强客户对我行的信任度，为后续业务合作奠定基础。

建议对该类客户建立持续跟踪机制，定期更新客户需求变化情况，动态优化营销策略，不断提升综合金融服务水平，推动客户贡献度稳步增长。

### 二、不满足贷款条件客户

该类客户虽暂未达到授信准入标准，但多数仍具有一定经营基础及发展潜力，通过持续跟踪与综合金融服务支持，具备进一步培育转化为有效融资客户的可能，是我行客户培育与业务储备的重要来源。

从当前情况来看，客户暂不满足贷款条件的原因主要包括以下几类：

1. 部分客户基础资料不完整，如财务报表、纳税记录、经营流水、上下游合同等证明材料不足，暂无法全面反映企业真实经营状况。建议主动指导客户补充相关材料，如完善财务报表、纳税证明、银行流水、经营合同等，协助客户进一步规范经营信息披露，提高信息透明度，在材料完善后可再次尝试申报授信。通过专业化服务帮助客户了解授信审批关注重点，提升客户融资成功率。
2. 部分客户经营年限较短、业务规模较小，财务指标尚未达到授信准入要求，如收入规模、利润水平、资产负债结构等未满足相关标准。建议重点加强基础金融服务合作，提升客户在我行的资金沉淀及业务往来频率，为后续融资条件改善创造基础。在客户资金规模逐步提升、经营情况趋于稳定后，可重新评估融资可行性。
3. 部分客户征信情况存在一定瑕疵，如历史逾期记录、对外负债偏高等因素影响授信审批。建议建立持续跟踪机制，定期了解客户经营变化情况。
4. 部分客户经营稳定性有待进一步观察，如行业波动较大或企业处于成长初期阶段。建议建立持续跟踪机制，定期了解客户经营变化情况。

### 三、产品匹配度不高客户

该类客户通常已与我行建立一定业务联系，但现有合作产品与客户实际经营需求契合度不高，导致业务合作深度和广度不足，客户综合贡献度有待进一步提升。通过持续开展需求挖掘与产品适配优化，该类客户具备较大的综合营销空间，是推动客户价值提升的重要目标客群。

从客户实际情况来看，产品匹配度不高的原因主要体现在以下几个方面：

1. 客户当前业务需求与我行已合作产品之间存在偏差，未能充分覆盖客户在资金结算、资金管理、融资支持或资产配置等方面的真实需求。
```

Create `backend/tools/import_phmarketing_golden.py`:

```python
#!/usr/bin/env python3
"""把对公普惠客户潜力营销 golden JSON 导入 data/golden/golden_test.db。

用法:
    cd backend
    python tools/import_phmarketing_golden.py
"""
from __future__ import annotations

import json
import sqlite3
import sys
from pathlib import Path

PROJECT_ROOT = Path(__file__).resolve().parent.parent
DB_PATH = PROJECT_ROOT / "data" / "golden" / "golden_test.db"
JSON_PATH = PROJECT_ROOT / "data" / "golden" / "对公普惠客户潜力营销_golden_items.json"
DOC_PATH = PROJECT_ROOT / "data" / "samples" / "step2-文档萃取" / "对公普惠客户潜力营销_访谈提纲模板.md"


def get_db() -> sqlite3.Connection:
    DB_PATH.parent.mkdir(parents=True, exist_ok=True)
    conn = sqlite3.connect(str(DB_PATH))
    conn.execute("PRAGMA foreign_keys = ON")
    conn.row_factory = sqlite3.Row
    return conn


def init_schema(conn: sqlite3.Connection) -> None:
    """仅创建表结构（幂等），不写入种子数据。"""
    schema = """
    CREATE TABLE IF NOT EXISTS golden_scenarios (
        id            INTEGER PRIMARY KEY AUTOINCREMENT,
        name          TEXT    NOT NULL UNIQUE,
        description   TEXT,
        domain        TEXT    DEFAULT '通用',
        created_at    TEXT    DEFAULT (datetime('now','localtime'))
    );
    CREATE TABLE IF NOT EXISTS golden_documents (
        id            INTEGER PRIMARY KEY AUTOINCREMENT,
        scenario_id   INTEGER NOT NULL REFERENCES golden_scenarios(id) ON DELETE CASCADE,
        filename      TEXT    NOT NULL,
        content       TEXT    NOT NULL,
        source_type   TEXT    CHECK(source_type IN ('制度','纪要','案例','访谈','培训','其他')),
        created_at    TEXT    DEFAULT (datetime('now','localtime'))
    );
    CREATE TABLE IF NOT EXISTS golden_items (
        id            INTEGER PRIMARY KEY AUTOINCREMENT,
        scenario_id   INTEGER NOT NULL REFERENCES golden_scenarios(id) ON DELETE CASCADE,
        document_id   INTEGER REFERENCES golden_documents(id) ON DELETE SET NULL,
        知识编号       TEXT,
        环节           TEXT,
        具体方法       TEXT    NOT NULL,
        知识类型       TEXT    CHECK(知识类型 IN ('判断规则','操作流程','反模式')),
        适用条件       TEXT,
        判断逻辑       TEXT,
        反模式踩坑提示  TEXT,
        经验判断       TEXT,
        适用边界       TEXT,
        例外情形       TEXT,
        来源文档       TEXT,
        来源位置       TEXT,
        置信度         TEXT    CHECK(置信度 IN ('高','中','低')),
        贡献专家       TEXT,
        证据数         INTEGER DEFAULT 0,
        突破数         INTEGER DEFAULT 0,
        created_at    TEXT    DEFAULT (datetime('now','localtime'))
    );
    CREATE INDEX IF NOT EXISTS idx_items_scenario ON golden_items(scenario_id);
    CREATE INDEX IF NOT EXISTS idx_items_document ON golden_items(document_id);
    CREATE INDEX IF NOT EXISTS idx_documents_scenario ON golden_documents(scenario_id);
    """
    conn.executescript(schema)


def import_golden() -> None:
    if not JSON_PATH.is_file():
        print(f"[ERROR] 找不到 golden JSON: {JSON_PATH}")
        sys.exit(1)

    with JSON_PATH.open(encoding="utf-8") as f:
        payload = json.load(f)

    scenario = payload["scenario"]
    doc_meta = payload.get("document", {})
    items = payload["items"]

    conn = get_db()
    init_schema(conn)
    cur = conn.cursor()

    # 插入或复用场景
    row = cur.execute(
        "SELECT id FROM golden_scenarios WHERE name = ?", (scenario["name"],)
    ).fetchone()
    if row:
        scenario_id = row["id"]
        print(f"[SKIP] 场景已存在: {scenario['name']} (id={scenario_id})")
    else:
        cur.execute(
            "INSERT INTO golden_scenarios (name, description, domain) VALUES (?,?,?)",
            (scenario["name"], scenario.get("description", ""), scenario.get("domain", "银行信贷")),
        )
        scenario_id = cur.lastrowid
        print(f"[OK] 新建场景: {scenario['name']} (id={scenario_id})")

    # 插入源文档
    doc_content = DOC_PATH.read_text(encoding="utf-8") if DOC_PATH.is_file() else ""
    doc_row = cur.execute(
        "SELECT id FROM golden_documents WHERE scenario_id = ? AND filename = ?",
        (scenario_id, doc_meta.get("filename", "")),
    ).fetchone()
    if doc_row:
        document_id = doc_row["id"]
        print(f"[SKIP] 文档已存在: {doc_meta.get('filename', '')}")
    else:
        cur.execute(
            "INSERT INTO golden_documents (scenario_id, filename, content, source_type) VALUES (?,?,?,?)",
            (scenario_id, doc_meta.get("filename", ""), doc_content,
             doc_meta.get("source_type", "访谈")),
        )
        document_id = cur.lastrowid
        print(f"[OK] 新建文档: {doc_meta.get('filename', '')} (id={document_id})")

    inserted = 0
    skipped = 0
    for item in items:
        编号 = item.get("知识编号")
        existing = cur.execute(
            "SELECT id FROM golden_items WHERE scenario_id = ? AND 知识编号 = ?",
            (scenario_id, 编号),
        ).fetchone()
        if existing:
            skipped += 1
            continue
        cur.execute(
            """INSERT INTO golden_items (
                scenario_id, document_id, 知识编号, 环节, 具体方法, 知识类型,
                适用条件, 判断逻辑, 反模式踩坑提示, 经验判断, 适用边界, 例外情形,
                来源文档, 来源位置, 置信度, 贡献专家, 证据数, 突破数
            ) VALUES (?,?,?,?,?,?,?,?,?,?,?,?,?,?,?,?,?,?)""",
            (
                scenario_id, document_id,
                编号, item.get("环节"), item["具体方法"], item.get("知识类型"),
                item.get("适用条件"), item.get("判断逻辑"), item.get("反模式踩坑提示"),
                item.get("经验判断"), item.get("适用边界"), item.get("例外情形"),
                item.get("来源文档"), item.get("来源位置"), item.get("置信度"),
                item.get("贡献专家"), item.get("证据数", 0), item.get("突破数", 0),
            ),
        )
        inserted += 1

    conn.commit()
    conn.close()
    print(f"[OK] 导入完成: 新增 {inserted} 条, 跳过 {skipped} 条, 共 {len(items)} 条")


if __name__ == "__main__":
    import_golden()
```

```python
import json
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parent))

import knowledge_base as kb

CASE_DIR = Path(__file__).resolve().parent.parent / "data" / "test-cases"
FILES = [
    "case-phmarketing-01_无融资需求.json",
    "case-phmarketing-02_不满足准入.json",
    "case-phmarketing-03_产品不匹配.json",
]
TAGS = "对公普惠客户潜力营销,营销,验证"
SOURCE = "plan_import"


def import_cases() -> None:
    kb.init_db()
    for filename in FILES:
        path = CASE_DIR / filename
        if not path.is_file():
            print(f"[WARN] 跳过不存在的文件: {path}")
            continue
        with path.open(encoding="utf-8") as f:
            data = json.load(f)
        case_uid = kb.add_verification_case(
            name=data["name"],
            input_data=data["input"],
            description=data.get("description", ""),
            expected_output=data.get("expected_output", {}),
            tags=TAGS,
            source=SOURCE,
            skill_id="",
        )
        print(f"[OK] 导入 {filename} -> {case_uid}")


if __name__ == "__main__":
    import_cases()
```
