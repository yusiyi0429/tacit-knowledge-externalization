# Golden 知识库数据模拟指南

## 概述

golden 知识库是【隐性知识显性化】项目的「金色标准」——它是 Agent Skill 生成时的知识源，
也是验证 pipeline 输出质量的对比基准。本指南教你如何从零构造一套完整的 golden 数据。

---

## 一、数据模型关系

```
golden_scenario (1) ──→ (N) golden_document
                                      │
                                      ├── (N) golden_items (直接从文档提取)
                                      │
golden_scenario (1) ──→ (N) golden_items   (不关联文档的独立条目)

golden_scenario (1) ──→ (N) verification_runs (Skill 验证记录)
```

核心表 `golden_items` 是数据构造的重心，每行代表一条"正确答案"。

---

## 二、构造步骤

### Step 1: 定义场景

```sql
INSERT INTO golden_scenarios (name, description, domain) VALUES
('科技型企业普惠贷款全流程管理',
 '面向高新技术企业、专精特新企业等科创属性企业的普惠贷款营销、贷后管理与不良分析全流程知识萃取',
 '银行信贷');
```

一条场景就够了——多场景时按业务领域拆分。

### Step 2: 准备源文档

源文档是知识提取的素材，分四种类型：

| 类型 | 示例 | 含有哪种知识 |
|------|------|-------------|
| **制度** | 银行信贷管理办法、监管制度、产品手册 | 标准化操作流程、规则条款 |
| **案例** | 真实贷款审查复盘记录 | 反模式、破例逻辑、专家直觉 |
| **纪要** | 专家访谈会议记录 | 经验判断、隐性规则 |
| **培训** | 条线培训教材 | 标准话术、常见误区 |

**制度文档的关键要素**：
- 业务概述（定义、适用范围、政策背景）
- 流程步骤（第1步→第2步→第3步）
- 准入条件和排除规则
- 产品参数（额度/利率/期限/担保方式）

**案例复盘的关键要素**（五段式结构）：
- 背景 / 情境 —— 什么客户、什么申请
- 当时怎么判断的 —— 专家内心活动
- 结果 —— 贷后走向
- 如果重来 —— 事后反思
- 养成的习惯 / 条件反射 —— 最珍贵的隐性信号

**案例复盘写作模板**：
```
案例标题：[一句话描述]
背景 / 情境：[客户画像 + 申请场景 + 关键数据]
当时怎么判断的？采取了什么行动？
  [不能只写"我觉得不对劲"——要写察觉到什么信号、做了哪些非常规操作]
结果：[贷后实际走向，逾期/回收/坏账]
如果重来一次：[漏掉了什么信号、应该多做什么]
这次经历让你养成了什么习惯 / 条件反射？
```
**关键**：案例复盘的价值不在"结果"而在"怎么判断的"和"养成的习惯"——这两部分才是真正的隐性知识。

### Step 3: 从文档提取知识条目

每个源文档提取 N 条知识，字段填充规则：

| 字段 | 制度文档 (KN-001~021) | 案例复盘 (KN-022~029) |
|------|----------------------|----------------------|
| 环节 | 客户筛选/营销策略/业务办理... | 贷前尽调/审批决策/贷后监控 |
| 具体方法 | 原文转述的操作步骤 | 专家具体做了什么 |
| 知识类型 | 操作流程 | 判断规则 / 反模式 |
| 判断逻辑 | 如有条件判断就填 | **必填** — IF-THEN 结构 |
| 反模式踩坑提示 | 可选 | **必填** — 踩过的坑 |
| 经验判断 | 无 | **必填** — 专家的直觉 |
| 适用边界 | 可选 | 此知识不适用的场景 |
| 例外情形 | 无 | 何时可以破例 |
| 证据数 | 0 | **1** (案例就是证据) |
| 突破数 | 0 | **1** (案例证明规则被突破) |
| 置信度 | 高 | 高 |

**区分制度化知识 (N=21) 与隐性经验 (N=8) 的核心差异**：

| 维度 | 制度化知识 | 隐性经验 |
|------|-----------|---------|
| 来源 | 制度手册、产品文档 | 案例复盘、专家访谈 |
| 填充项 | 具体方法 + 适用条件 + 判断逻辑 | + 反模式 + 经验判断 + 适用边界 + 例外情形 |
| 证据数 | 0 (来自制度本身) | 1 (来自真实案例) |
| 突破数 | 0 | 1 (揭示了原有规则的不足) |
| 保鲜度审计时 | 理论完善但缺乏实战验证 | 有实证支撑但可能适用范围窄 |

## 三、数据质量要求

构造完 golden_items 后，用以下 SQL 自检：

```sql
-- 1. 基础完整性
SELECT
    COUNT(*)                     AS total,
    SUM(CASE WHEN 判断逻辑 IS NOT NULL AND 判断逻辑 != '' THEN 1 ELSE 0 END) AS 有判断逻辑,
    SUM(CASE WHEN 反模式踩坑提示 IS NOT NULL AND 反模式踩坑提示 != '' THEN 1 ELSE 0 END) AS 有反模式,
    SUM(CASE WHEN 经验判断 IS NOT NULL AND 经验判断 != '' THEN 1 ELSE 0 END) AS 有经验判断,
    SUM(CASE WHEN 适用边界 IS NOT NULL AND 适用边界 != '' THEN 1 ELSE 0 END) AS 有适用边界,
    SUM(CASE WHEN 例外情形 IS NOT NULL AND 例外情形 != '' THEN 1 ELSE 0 END) AS 有例外情形
FROM golden_items;

-- 2. 来源分布
SELECT
    COALESCE(gd.source_type, '无来源') AS 来源,
    COUNT(*) AS 条数
FROM golden_items gi
LEFT JOIN golden_documents gd ON gi.document_id = gd.id
GROUP BY gd.source_type
ORDER BY COUNT(*) DESC;

-- 3. 置信度分布
SELECT 置信度, COUNT(*) AS n FROM golden_items GROUP BY 置信度;

-- 4. 各环节覆盖情况
SELECT 环节, COUNT(*) AS n
FROM golden_items
GROUP BY 环节
ORDER BY n DESC;

-- 5. 隐性经验占比 (黄金指标)
SELECT
    SUM(CASE WHEN 反模式踩坑提示 IS NOT NULL AND 反模式踩坑提示 != '' THEN 1 ELSE 0 END) AS 隐性条目数,
    COUNT(*) AS 总条目数,
    ROUND(SUM(CASE WHEN 反模式踩坑提示 IS NOT NULL AND 反模式踩坑提示 != '' THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 1) AS 隐性占比
FROM golden_items;
```

**推荐质量标准**：
- 判断逻辑填充率 ≥ 60%
- 反模式覆盖率 ≥ 30%
- 经验判断填充率 ≥ 20%
- 案例来源占比 ≥ 25%（否则全是理论，没有实战）
- 置信度「高」占比 ≥ 70%

## 四、数据规模建议

| 阶段 | 场景数 | 文档数 | 知识条数 | 制度:案例比 |
|------|--------|--------|---------|-----------|
| MVP (当前) | 1 | 4 | 29 | 21:8 (72:28) |
| 生产就绪 | 1 | 10-15 | 80-120 | 60:40 |
| 多场景 | 3-5 | 30-50 | 200-500 | 55:45 |
| 企业级 | 10+ | 100+ | 1000+ | 50:50 |

扩容时优先增加**案例复盘文档**和**场景微调文档**——它们最能提升 Agent Skill 的实战判断力。
