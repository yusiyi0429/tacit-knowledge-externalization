# 多源碎片化知识模拟数据（对齐 Step1 场景锚定）

## 场景定义

**场景名称**：科技型企业普惠贷款全流程管理

**3 个子场景**：
| 子场景 | 核心内容 |
|--------|---------|
| 科技型企业普惠贷款营销 | 客户筛选 → 数据匹配 → 原因归因 → 决策建议 |
| 普惠贷款贷后管理 | 贷后检查、到期管理、逾期处理 |
| 普惠不良贷款分析 | 不良统计、机构/客户维度分析、风险归因 |

**知识列（Step1 定义）**：环节、访谈方向、具体方法、知识类型（判断规则/操作流程/反模式）、知识引用、适用条件、判断逻辑、反模式/踩坑提示、经验判断、适用边界、例外情形、来源文档、来源位置、置信度、贡献专家、证据数、突破数

## 融合测试特征

- **重叠知识**：代发工资预警阈值、专利质押回收率、初创企业审慎系数等出现在多个文件中 → 应检出重复
- **互补知识**：01侧重营销筛选规则，02侧重贷后监控方法，04侧重不良归因分析 → 融合后覆盖全流程
- **冲突知识**：03中张风控和李经理对「专利被引用次数作为评价指标」意见分歧 → 应检出冲突
- **隐性经验**：每个文件都有"制度上没有写的"土办法和个人经验

## 测试路径

1. 在 Step1 完成场景锚定（按场景名称、内容、3 个子场景执行）
2. 进入 Step2，切换到「多源融合」模式
3. 批量上传 6 个文件
4. 观察：系统 prompt 中是否包含 Step1 定义的知识列？提取后的结果是否按子场景分类？
5. 观察融合结果中的去重、冲突检测、来源分布
6. 进入 Step3，确认融合结果能正常加载进行知识校验
