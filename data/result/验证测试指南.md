# Agent Skill 验证测试指南

## 概述

本验证包用于测试 `科技型企业普惠贷款全流程管理` Agent Skill 的正确性和有效性。验证包包含以下内容：

```
data/result/
├── SKILL.md                              ← Agent Skill 定义文件
├── COT_科技型企业普惠贷款全流程管理_7d35c5.md   ← 思维链交付物
├── QA_科技型企业普惠贷款全流程管理_7d35c5.json  ← 问答对 (JSON)
├── QA_科技型企业普惠贷款全流程管理_7d35c5.md    ← 问答对 (Markdown)
├── golden/
│   └── golden_test.db                    ← 知识库 (SQLite)
├── test-data/
│   ├── case-01_无融资需求-专精特新.json    ← 测试用例 1
│   ├── case-02_流水异常-芯片设计.json      ← 测试用例 2
│   ├── case-03_贷后预警-研发骤降.json      ← 测试用例 3
│   └── case-04_不良复盘-征信核查缺失.json  ← 测试用例 4
└── 验证测试指南.md                        ← 本文件
```

## 前置条件

### 1. 环境准备

- **Hermes Agent**（或与 OpenClaw / MCP 兼容的 Agent 运行环境）
- **SQLite MCP 工具**（需安装 `mcp__sqlite__read_query` 等 SQLite 工具）
- **SKILL.md 路径**：需将 `SKILL.md` 配置到 Agent 的 skill 目录中
- **golden 数据库路径**：将 `golden/golden_test.db` 放置于 Agent 可访问的路径，或修改 SKILL.md 中 `metadata.database` 字段为实际路径

### 2. 数据库连通性验证

```bash
# 确认 golden_test.db 可正常读取
sqlite3 data/result/golden/golden_test.db ".tables"
# 预期输出：golden_scenarios  golden_documents  golden_items  verification_runs

# 验证关键表中有数据
sqlite3 data/result/golden/golden_test.db "SELECT COUNT(*) FROM golden_items"
# 预期输出：29
```

## 测试用例

### 用例 1：无融资需求客户的营销策略推荐

**输入文件**：`test-data/case-01_无融资需求-专精特新.json`

| 项目 | 内容 |
|------|------|
| 场景 | 客户经理跟进一家省级专精特新企业 |
| 期望触发 Skill 环节 | 客户筛选 → 原因归因 → 营销策略 |
| 关键信号词 | 专精特新、信用快贷、无融资需求 |
| 预期输出 | 建议转向结算/理财服务，定期回访 |

**验证步骤**：
1. 将 case-01 的内容作为输入传递给 Agent
2. 检查 Agent 是否触发「科技型企业普惠贷款全流程管理」Skill
3. 检查输出是否含客户筛选结果（通过）
4. 检查原因归因是否归类为「无融资需求」
5. 检查营销建议是否包含结算/理财推荐

**预期评估报告要点**：
- KN-001 匹配：企业具备专精特新标签且未办理信用快贷 → 筛选通过
- 产品知识匹配：专精特新贷/善新贷
- 营销策略匹配：无融资需求客户 → 转向结算和理财服务
- 缺失信息提示：建议补充知识产权证书有效期

### 用例 2：流水异常检测与风控建议（核心测试）

**输入文件**：`test-data/case-02_流水异常-芯片设计.json`

| 项目 | 内容 |
|------|------|
| 场景 | 芯片设计企业申请 500 万贷款，流水存在季度末规律性大额进出 |
| 期望触发 Skill 环节 | 客户筛选 → 客户数据匹配 → 反模式匹配 |
| 关键信号词 | 高新技术企业、专精特新、流水、关联方 |
| 预期输出 | 流水真实性存疑，建议降额 + 追加担保 |

**验证步骤**：
1. 输入案例文档内容
2. 检查反模式匹配：季度末资金过桥、关联方资金往来
3. 检查决策建议：是否包含降额、追加实控人连带担保
4. 检查是否触发「二次征信核查」建议

**预期评估报告要点**：
- 步骤 1&2：客户资质筛选通过（高企+专精特新+专利）
- 反模式匹配：触发「季度末规律性大额进出」信号
- 建议动作：降额至 200 万以内、追加实际控制人连带责任保证、放款前做二次征信核查

### 用例 3：贷后预警——研发投入骤降 + 核心技术人员流失

**输入文件**：`test-data/case-03_贷后预警-研发骤降.json`

| 项目 | 内容 |
|------|------|
| 场景 | 生物医药企业季度贷后检查发现多项预警信号 |
| 期望触发 Skill 环节 | 贷后监控 → 风险归因 |
| 关键信号词 | 研发投入下降、技术人员离职、专利失效 |
| 预期输出 | 黄色/红色预警，建议启动贷后现场检查 |

**验证步骤**：
1. 输入贷后检查报告
2. 检查是否识别研发投入同比降幅（42% > 30% 阈值 → 黄色预警）
3. 检查是否识别核心技术人员离职（研发总监离职 → 红色预警维度）
4. 检查是否识别专利失效（1 项核心专利未缴年费）
5. 检查综合评估建议

**预期评估报告要点**：
- 双维预警触发：研发投入同比下降 42%（>30% 黄色预警）
- 核心技术岗位离职（研发总监→>20% 预警阈值）
- 科创属性衰减信号：专利失效 + 研发支出减少 + 无新专利申请
- 建议动作：启动贷后现场检查、评估持续经营能力、核实 B 轮融资进展

### 用例 4：不良贷款成因分析——征信核查缺失

**输入文件**：`test-data/case-04_不良复盘-征信核查缺失.json`

| 项目 | 内容 |
|------|------|
| 场景 | AI 视觉检测企业贷款后 6 个月逾期，复盘发现多项贷前/贷后疏漏 |
| 期望触发 Skill 环节 | 不良分析 → 风险归因 |
| 关键信号词 | 征信、二次核查、资金流向不符、预警缺失 |
| 预期输出 | 不良成因归类 + 流程改进建议 |

**验证步骤**：
1. 输入不良复盘案例
2. 检查是否识别「放款前未做二次征信核查」的流程缺失
3. 检查是否识别「资金流向与申请用途不符」
4. 检查是否输出不良成因归类分析

**预期评估报告要点**：
- 反模式匹配：放款前未二次查征信、资金用途不符
- 成因归因：贷前尽调不充分（未查实经营地址、未二次查征信）+ 预警指标不完善（未监控客户集中度风险）
- 建议：补充经营地址现场核实流程、放款前二次征信核查制度、增加核心客户变动预警指标

## 常见问题

**Q: Agent 未触发 Skill**
A: 检查输入文档是否包含触发关键词（参见 SKILL.md 第 2 节「触发规则」）。如文档类型或关键词不匹配，需补充或调整输入。

**Q: SQLite 查询返回空**
A: 确认 `golden/golden_test.db` 路径正确且 SKILL.md 中 `metadata.database` 字段指向正确路径。

**Q: 输出格式与 SKILL.md 模板不一致**
A: SKILL.md 第 5 节「评估输出模板」是推荐格式，实际输出可能因 Agent 实现有细微差异。主要验证知识匹配逻辑是否正确，而非格式完全一致。
